Se você abrir 10 vagas de emprego na área de Tecnologia — seja para Desenvolvedor, Product Owner, Scrum Master, QA ou Analista de Negócios —, pelo menos 8 vão exigir conhecimento em **Jira Software**.

Desenvolvido pela Atlassian, o Jira deixou de ser apenas um rastreador de bugs para se tornar o sistema nervoso central das empresas modernas. Dominar essa ferramenta é o atalho mais rápido para provar maturidade corporativa em entrevistas.

## 1. A Hierarquia do Jira (Como o Trabalho é Organizado)

O erro número um dos iniciantes é sair criando tarefas soltas sem organização. O Jira trabalha em uma estrutura de cascata lógica:

* **Projeto (Project):** O contêiner principal (ex: *Aplicativo Mobile Bancário*).
* **Épico (Epic):** Um grande objetivo de negócio que leva semanas ou meses para ser concluído (ex: *Sistema de Pagamentos via PIX*).
* **História de Usuário (Story):** Uma funcionalidade entregável que gera valor direto ao cliente (ex: *Como cliente, quero cadastrar uma chave PIX aleatória*).
* **Tarefa (Task) e Subtarefa (Sub-task):** O trabalho técnico necessário para construir a história (ex: *Criar tabela no banco de dados*, *Desenvolver tela de confirmação*).
* **Bug:** Qualquer defeito encontrado no sistema que precisa de correção.

## 2. Backlog vs. Quadro Ativo (Active Sprint)

Dentro de um projeto Scrum no Jira, você alterna entre duas telas principais:

1. **Product Backlog (A Sala de Espera):** É a lista infinita de ideias, melhorias e correções priorizadas pelo **Product Owner**. Nada aqui está sendo programado ainda; o PO está refinando os detalhes e escrevendo os Critérios de Aceite.
2. **Quadro da Sprint (A Linha de Produção):** Quando a equipe inicia um ciclo de trabalho (Sprint de 2 semanas), os cartões selecionados saem do Backlog e vão para o quadro visual com colunas como `A Fazer (To Do)`, `Em Progresso (In Progress)`, `Em Revisão (Code Review)` e `Concluído (Done)`.

## 3. Os 2 Relatórios Que Todo Gestor Olha

O grande diferencial do Jira sobre ferramentas simples (como o Trello) é a geração automática de métricas de previsibilidade:

* **Burndown Chart:** Mostra em tempo real se a equipe vai conseguir entregar tudo o que prometeu até o último dia da Sprint ou se o trabalho está atrasado.
* **Velocity Chart:** Calcula a média de pontos (*Story Points*) que a equipe entrega por Sprint, permitindo prever com precisão matemática quantos meses levará para finalizar um projeto inteiro.
