Quando um desenvolvedor diz "Terminei", o que isso realmente significa? Ele apenas escreveu o código? Ele testou? Ele subiu para o servidor? 

A falta de clareza nessa única palavra é o que causa o colapso de sistemas em sextas-feiras à noite. Para blindar a qualidade do produto, o Scrum utiliza duas travas de segurança essenciais: os **Critérios de Aceite** e a **Definition of Done (DoD)**. Confundir os dois é o erro número um de equipes imaturas.

## Critérios de Aceite (A Regra Específica)
Os Critérios de Aceite são regras de negócio exclusivas para **uma única História de Usuário**. Eles respondem à pergunta: *O que essa funcionalidade específica precisa fazer para o cliente ficar feliz?*

* **Quem escreve:** O Product Owner (PO).
* **Foco:** Comportamento do sistema.
* **Exemplo para um Cartão de "Login":** "O usuário deve ser bloqueado após 3 tentativas de senha incorreta". Isso só se aplica à tela de login.

## Definition of Done - DoD (A Regra Global)
A Definition of Done (Definição de Pronto) é um checklist técnico universal. Ela se aplica a **absolutamente todas as tarefas** da Sprint, seja a tela de login ou um botão de pagamento. Ela responde à pergunta: *O que nosso código precisa ter para não quebrar a empresa?*

* **Quem escreve:** A Equipe de Desenvolvimento (Developers).
* **Foco:** Qualidade técnica e engenharia de software.
* **Exemplo de Checklist DoD:** 
  1. O código foi revisado por outro programador (Code Review).
  2. Os testes automatizados passaram em 100%.
  3. A funcionalidade está homologada no ambiente de testes.

## O Fluxo de Segurança no Jira
Para uma tarefa ser arrastada para a coluna final "Concluído" no Jira Software, ela deve passar pelos dois filtros. O código deve atender aos Critérios de Aceite (o PO aprova) E deve cumprir o checklist da DoD (a engenharia aprova). Se faltar um dos dois, a tarefa volta para "Em Andamento".
